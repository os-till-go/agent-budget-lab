# 工具输出压缩：阅读记录与本版实现

阅读日期：2026-11-13。只采用论文原文、作者仓库和厂商工程资料。以下是有针对性的阅读，不是穷尽综述，也未运行第三方论文的完整实验。

核心判断：**已有大量直接研究，不能把“压缩工具输出”本身当作新贡献。值得先做的是可审计的小实验：关键条件丢失时，模型会猜、重查还是失败；恢复信息后是否仍节省总开销。**

## 直接相关的研究

| 资料 | 原文的主要发现或机制 | 对本 demo 的影响 |
|---|---|---|
| [Beyond Token Savings](https://arxiv.org/html/2609.32961v1)，2026-09，预印本 | 系统改变压缩对象、时机和强度，同时衡量任务成功、token、延迟及估算成本；减少 token 并不总能缩短执行时间，效果依赖模型和工作负载。 | 不预设完整输出或压缩必胜；逐题保留结果，分别记录累计输入、输出、调用数和耗时。 |
| [DTOC](https://arxiv.org/html/2609.26121v1)，2026，论文标注 Discovery Science 接收 | 外部保留完整输出，在活动上下文中隐藏输出，再由模型按需恢复；实验效果具有模型差异。 | 增加原始日志分段查询，并设置次数上限；这只是机制借鉴，不是 DTOC 复现。 |
| [The Complexity Trap](https://arxiv.org/html/2508.21433v2)，2025，本文阅读 v2 | SWE-agent 内比较隐藏旧 observation 和模型摘要；简单方法具有竞争力，摘要有时会延长轨迹。这里的旧输出隐藏与我们单条日志过滤有区别。 | 保留无需额外模型调用的简单基线，不把额外摘要器当作默认升级。 |
| [AgentDiet / Reducing Cost of LLM Agents with Trajectory Reduction](https://arxiv.org/html/2509.23586v2)，2026-03 修订 | 将历史中的无用、重复、过期信息分开处理；把反思调用开销和缓存折扣纳入成本。部分信息可通过额外调用恢复。 | 累计每次调用用量；当前规则压缩的模型调用为零。若以后增加摘要模型，必须将该调用纳入总账。 |
| [Context Is a Pipeline, Not a Window](https://arxiv.org/html/2610.36114v1)，2026-10，预印本 | 工具输出到模型之间可能发生截断；受控实验中，损失先表现为额外工作，未必立刻表现为答错。作者也明确保留了因果与泛化限制。 | 记录实际发送的视图与完整日志哈希；按整行选择，明确省略；允许重查后重新统计总用量。 |
| [LLMLingua-2](https://arxiv.org/abs/2403.12968)，2024，ACL | 将任务无关的抽取式压缩建模为 token 分类，用较小编码器降低压缩延迟。 | 是以后可加的学习型基线；当前不下载权重、不训练，也不以我们的行过滤冒称实现它。 |
| [Anthropic: Effective context engineering for AI agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents)，2025-09 | 用轻量引用保留外部材料，再按需加载；运行时探索也会带来延迟与工具使用开销。 | 保留原始日志、公开查询接口，观察模型是否会使用，以及是否反复查询同一段。 |

## 公开实现核查与边界

- **Complexity Trap**：[作者仓库](https://github.com/JetBrains-Research/the-complexity-trap) 包含 SWE-agent 实现、配置和 `sweagent run-batch` 实验入口，README 链接轨迹数据。已看到入口，不等于复现成功；原文开源模型实验使用 H200 集群，云模型还需要 API。
- **DTOC**：[作者链接的仓库](https://github.com/chaturvediabhay24/opencode) 实际可读。README 说明消息变换 hook 与 `manage_context` 恢复机制；`package.json` 为 TypeScript/Bun 项目，声明 MIT、`bun test`、`tsc` 与 OpenCode >=1.17.7 依赖。未安装、未核验其论文评测脚本和数据，不标注为已验证可复现。
- **LLMLingua**：[Microsoft 仓库](https://github.com/microsoft/LLMLingua) 提供压缩实现和权重使用说明；本次仅检查公开说明，没有安装依赖、下载权重或验证我们的硬件速度。
- 其余论文仅用于研究设计参考，本次没有确认可直接运行的整套复现实验，不建议仅凭论文中的数字立项。

## 从阅读到实现的取舍

本版保留原来的三个教学案例，另外增加一套成对诊断任务：同一任务描述、相同候选顺序、相同代码，只有日志的运行条件不同。模型看不到任务 ID、变体标签、正确选项和隐藏验收结果。

四个常规条件是完整输出、错误过滤、配置与错误保留、无日志。额外 oracle 条件直接使用人工标记的配置行，只作参考，不作为自动方法的成果。

`structured` 按 `[CONFIG]` 等通用行类型筛选，没有按答案选择字段；但这个结构化标记也是人工生成器提供的便利。因此它仍是受控实验，不能代表任意真实日志。小型对照可以检查机制，不能证明真实任务发生频率。

下一步若继续研究，应先让更强的模型在完整日志上稳定通过成对任务，再冻结开发协议、评测留出任务，最后引入真实仓库日志。直接堆更多合成噪声或依照失败测试不断改题，都不能代替这一步。
