# 真实模型实验：启动、协议与结果边界

2026-11-14 补充：[7B 模型的逐题诊断与新增小实验](qwen7-diagnostics.md)。它尚未形成可靠的完整日志成对参照；网页默认模型和 diagnostic-v3 均保持原样。

这是选择预定义补丁的诊断实验。补丁是真实 Python 函数，验收在模型最终提交之后执行；模型不会自由生成或执行代码。

## 运行

原有两页仍可离线使用。第三页需要模型服务，默认配置为本机 Ollama 上已经安装的 `llama3.2:1b`。软件不自动安装 Ollama、不下载模型；其他电脑需自行安装并准备模型。

```powershell
python server.py --open
```

打开第三页“真实模型”。先选择一个任务对，重查为 0，运行四组对照；再设置允许 1 或 2 次重查，比较累计用量。后台逐题保存 `runs/<id>.json`，页面可导出完整记录。刷新页面会清空页面视图，后台任务继续；可从本地文件恢复记录。

更换已经安装的 Ollama 模型：

```powershell
$env:ABL_MODEL='你的模型名'
python server.py --open
```

连接支持 JSON 输出的 Chat Completions 兼容服务：

```powershell
$env:ABL_PROVIDER='compatible'
$env:ABL_BASE_URL='https://你的服务地址/v1'
$env:ABL_MODEL='你的模型名'
# 在本地启动环境中设置 ABL_API_KEY；不要放进源码、截图或结果文件。
python server.py --open
```

服务需要支持 `response_format=json_object`、`temperature`、`max_tokens`。此兼容通道已做离线协议检查，尚未用真实远程账户端到端验证；原生 Ollama 通道已真实验证。远程请求可能收费，token 不等于账单。地址只允许 HTTPS 或本机 HTTP，不跟随重定向、不使用环境代理。

命令行和界面共享同一引擎：

```powershell
python scripts/run_model_experiment.py --tasks threshold-0 threshold-1 --queries 0
python scripts/run_model_experiment.py --tasks threshold-0 threshold-1 --queries 2
```

## 固定协议 diagnostic-v3

- 每一对任务的描述、代码、候选和非条件日志相同，只有部署约定变化；同一个候选不能同时通过两个变体。选项顺序随种子改变，但同一对保持一致。
- “重复”使用基础种子加重复序号，因此也改变候选顺序和背景日志；这是配对种子试验，不是对完全相同提示做独立随机采样。数据哈希覆盖生成的公开视图与运行约定，原始请求和响应另存于 trace。
- 开发集：零值处理、Unicode 规范化、CSV 分隔符三族，每族两个变体，共 6 题。原来的教学三例不作为新增正式测试。
- 预留集：舍入和大小写键比较两族，共 4 题。浏览器禁止运行；CLI 必须显式 `--allow-holdout`。本次没有向模型运行预留题；它们是作者可见的合成任务，不能称作外部盲测。
- 相同模型、解码参数、任务与输出格式；条件独立对话。输入内容包括原始或过滤后的工具视图，不包括正确答案、隐藏测试、方法名或任务变体名。
- 无日志对照永远不允许重查。其他三组在同一次实验中共享查询接口和上限。每条最多 3 次模型调用；最后一次必须提交补丁。
- 原生 Ollama 在查询额度耗尽时用 JSON schema 限制可用动作；兼容接口依靠提示与后端校验，违规输出计失败，不偷偷修正答案。
- 重查返回原始日志的指定行，最多 100 行。默认日志共 65 行，因此一次完整读取通常就能恢复所有信息；额度为 2 时允许重复读，观察模型的查询行为。
- 过滤按整行保留并计入省略提示；默认压缩字符上限 1200，完整输出不受此上限限制。它是自然长度对照，不是等 token 压缩算法竞赛。
- 所有压缩均为本地确定性规则，压缩模型调用数为 0。若增加模型摘要，需要另外接入并累计用量。
- 成功要求全部验收通过。格式违规、越权查询、请求失败单独记录；请求失败后整批停止，不自动重试。
- 每次请求记录完整可见消息、响应、模型 ID、终止原因、服务报告 token、耗时；批次记录提示版本、数据哈希、Ollama 权重 digest。用量缺失为 `null`，缓存未知也为 `null`。
- `input_tokens` 跨调用相加，包含反复发送的历史。耗时包含请求处理与可能的模型加载；缓存、冷启动、运行顺序会影响数值。没有价格配置，货币成本不估算。

## 2026-11-13 本地实测

模型：`llama3.2:1b`，Q8_0；digest `baf6a787fdffd633537aa2eb51cfd54cb93ff08e28040095462bb63daf552878`。temperature=0，num_ctx=8192，输出上限 400；种子 7，每题每条件一次，全部 6 个开发题。每个补丁有 5 项验收。

| 输入方式 | 不重查：全验收通过 | 不重查：累计输入 token | 最多两次重查：全验收通过 | 重查后：累计输入 token | 实际重查 / 模型调用 |
|---|---:|---:|---:|---:|---:|
| 完整输出 | 1/6 | 7,343 | 2/6 | 24,441 | 12 / 18 |
| 错误过滤 | 0/6 | 2,102 | 2/6 | 20,839 | 12 / 18 |
| 配置与错误保留 | 2/6 | 2,387 | 2/6 | 9,536 | 12 / 18 |
| 无日志对照 | 1/6 | 1,934 | 1/6 | 1,934 | 0 / 6 |

两轮四组的“同一对两个变体均成功”都是 **0/3**。单步错误过滤另有一条无效回答，按失败计入 0/6。没有请求传输失败。

这些结果表明：**当前小模型尚未通过实验有效性检查，不能用它断言压缩保留了诊断能力。** 允许查询后，它在三个可查询条件下都用满了额度。查询权限不等于有效的信息寻找能力；累计输入量明显上升，也不自动换来可靠成功。

目前仅验证了真实调用、重查执行和记录流程。每个条件只有 6 个开发任务、一次运行，提示还在开发阶段；不做显著性结论或方法排名。后续首先应更换有能力通过完整日志对照的模型，而不是为了得到预期优势继续调压缩规则。

### 保留的调试失败

- `diagnostic-v1`，批次 `e664be50182d`：8 条调用全部选择 A，并照抄提示中的示例解释。完整输出也不成功。首次调用包含约 82 秒冷启动，不与后续暖启动耗时比较。
- `diagnostic-v2`，批次 `650dec3e0cc4`：去掉示例后，多数输出在禁止查询时仍请求日志，协议遵循不足。
- `diagnostic-v3` 增加按剩余额度限制动作的原生结构化输出，并明确单步必须提交。这改变了协议，v1/v2 与 v3 不合并统计。

完整原始记录位于 `examples/model/`，只供审阅；界面不把这些文件加载成实时结果。协议和数据改动后应生成新的版本与结果。
