# 7B 模型诊断：读懂规则与选对补丁是两回事

整理日期：2026-11-14。分支 `research/qwen7-diagnostics`。本轮只研究 Agent Budget Lab，不涉及其他项目。

## 这轮做了什么

先审阅工作区已有的两批真实本地调用，再新增 6 次调用：四次把同一零值约定改写成直白英文，两次只问应有输出、不提供候选代码。没有重跑相同的既有批次，也没有运行四道预留任务。

模型为本机已有 `qwen2.5:7b`，digest `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`；无外部模型 API 调用。原生 Ollama、temperature=0、上下文 8192。补丁选择输出上限 400 token；单独的规则解释检查上限 100。

## 先看已有记录

原记录均为 `diagnostic-v3`，种子 7、8，6 道开发题，禁止重查。两轮会改变候选顺序与背景日志，不是对完全相同提示做独立采样。

| 输入 | 单题全部验收通过 | 成对两变体均通过 | 累计输入 token |
|---|---:|---:|---:|

“对次”是一对任务在一个种子下的结果：3 对 × 2 个种子，共 6 对次。oracle 已经直接给出人工定位的配置行，它不是自动压缩方法的成绩。

## 观察到的具体失败

1. **零值是有效值，却选了把它改成默认值的代码。** `threshold-0` 的日志要求 `zero_is=explicit_value`；完整日志在两个种子下都失败。部分解释甚至同时承认“0 不该变 10”，又选择会把 0 变 10 的实现。
2. **读到了 NFC/NFKC 区别，选项编号仍可能错。** 种子 7 的一条回答明确说应该 NFKC，却选择了 NFC 实现。
3. **逗号/分号判断与解释自相矛盾。** 一条回答说当前应为 comma，却选择了 semicolon 候选。模型给出的理由不能替代实际代码验收。

这些观察不能直接归因于某一内部原因，但提示我们：成功率中混合了条件理解、代码理解与候选选择问题。尚不适合把全部失败解释为日志压缩损失。

## 新实验一：换成人话是否改善零值任务？

保持两个零值任务、候选、选项顺序、模型、种子、验收器相同，仅将 oracle 配置行的文字改写：

- 有效零值：`If value is None, return the default 10. If value is zero, return zero. Otherwise convert value to an integer. Keep negative values unchanged.`
- 默认值标记：`If value is None or zero, return the default 10. Otherwise convert value to an integer. Keep negative values unchanged.`

没有给模型正确补丁 ID 或隐藏验收结果。因为是在看到开发失败后设计的检查，这属于调试诊断，不是新的独立测试。

| 条件 | 原配置行 | 直白英文 |
|---|---:|---:|
| 0 是有效值，种子 7 | 失败 | 失败 |
| 0 表示默认值，种子 7 | 通过 | 通过 |
| 0 是有效值，种子 8 | 失败 | 失败 |
| 0 表示默认值，种子 8 | 通过 | 通过 |

结果仍为 2/4，成对全对 0/2，未观察到这次措辞修改带来的改善。新增 4 次实际调用，输入 1,420 token、输出 268 token；总请求耗时约 16.3 秒。缓存/冷启动影响未单独控制，不作速度比较。

原始记录：[措辞诊断](../examples/model/qwen25-7b-plain-wording.json)。

## 新实验二：只问规则，不让它选代码

使用上面的两个直白约定，不提供候选代码。让模型分别回答 `None`、`0`、`-2` 应得到什么。

| 约定 | 模型返回 | 与约定是否一致 |
|---|---|---|
| 0 有效 | None → 10；0 → 0；-2 → -2 | 一致 |
| 0 表示默认值 | None → 10；0 → 10；-2 → -2 | 一致 |

两次实际调用都通过这项检查。它表明模型在这个更简单的任务里能正确报告期望行为；不能据此断言它一定读懂了 Python 或定位到了补丁编号错误的唯一原因。此任务的提示与输出格式已经改变，成绩不与补丁选择准确率合并。

原始记录：[规则解释诊断](../examples/model/qwen25-7b-rule-interpretation.json)。

## 可以得出的判断

7B 在这些开发题上的成绩高于已有 1B 记录，但重复设置并不完全相同，不能作为模型排名；完整日志仍未形成可靠的成对参照。当前值得检查的是 **“正确行为 → 候选代码”的映射**：模型可能说对规则，最终却交错补丁。

下一轮可比较直接选择与“先报告期望行为，再选择补丁”的两种接口，并对同一候选代码进行位置/编号平衡。需要另定协议版本，完整保留失败，不能把后处理替模型改成正确答案。接口可靠之后，再回到压缩与有限重查。

这里没有新的压缩方法胜负结论，也没有大样本、留出集或真实代码仓库泛化证据。

## 如何复跑这两项小诊断

默认只查看计划，不调用模型：

```powershell
python scripts/probe_contract_wording.py
python scripts/probe_contract_understanding.py
```

本地模型已准备好后，在当前启动进程中指定模型再显式运行：

```powershell
$env:ABL_PROVIDER='ollama'
$env:ABL_MODEL='qwen2.5:7b'
$env:ABL_BASE_URL='http://127.0.0.1:11434'
python scripts/probe_contract_wording.py --run
python scripts/probe_contract_understanding.py --run
```

措辞检查核对基线模型 digest、数据哈希与提示哈希。结果写入忽略版本控制的 `runs/`；本文链接的是人工归档的真实记录，网页不会把它们当成实时运行。
