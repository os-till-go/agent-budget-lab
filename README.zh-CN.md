# Agent Budget Lab：用两个小实验理解 Agent 的成本与可靠性

本地浏览器交互工具，中文界面。原有两个实验无需 API Key；新增第三页可调用真实模型，比较成对任务、无日志对照和有限重查。它是概念验证与学习工具，尚不是论文复现或正式基准。

**本轮新增**：[文献阅读与设计依据](docs/related-work.md) · [真实模型启动、固定协议与实测结果](docs/model-experiment.md)。本机已用 Ollama 的 `llama3.2:1b` 跑通真实调用；小模型尚不能稳定读懂成对条件，暂不能得出压缩方法优劣结论。

**7B 开发诊断**：[读懂规则与选对补丁是两回事](docs/qwen7-diagnostics.md)。新增小实验中，模型能直接报对零值处理的期望输出，却仍可能选错候选代码；原始记录和复跑脚本一并保留。

## 启动

需要 Python 3.10+ 和 scikit-learn。建议使用 Python 3.11 或 3.12。

Windows 双击 `start-demo.cmd`，保留启动窗口。也可以在本目录运行：

```powershell
python -m pip install -r requirements.txt  # 仅缺少依赖时需要
python server.py
```

打开 **http://127.0.0.1:8767**。按 Ctrl+C 停止。端口被占用时用 `python server.py --port 8768`，再打开对应端口。

服务器只绑定本机。分享时发送整个 Release zip，让对方解压启动；仅发送 localhost 链接不能让其他电脑访问。也可现场共享屏幕演示。原有两个实验不调用网络模型；第三页需准备本地模型，或配置可能收费的远程 API。具体配置见上方说明。

## 三分钟演示

首次使用先读页面上的场景与输入示例，再按三步提示操作；“演示指南”可展开完整流程，“几个词先说清楚”解释日志、补丁、验收、token 与种子。每个参数旁说明它改变什么，以及为什么要改变。

1. 实验 01 默认选择 Unicode 案例和“只留错误”。点击运行修复：日志短了，但固定诊断规则没有拿到运行条件，补丁未通过全部验收。
2. 切换“保留环境线索”，再次运行。比较字符数和通过用例；或点击“比较全部三种方式”。
3. 删除右侧日志中的 `normalization=NFKC`，再运行，亲自检验该线索的作用。也可自己选择修复选项，观察诊断规则的限制。
4. 实验 02 保持种子 7、初筛 8 条、预算 144，运行三种策略。容易样本前缀会使关键词捷径在初筛中并列第一；看完整开发集和独立测试的真实得分。
5. 改为“打散样本”再运行，然后增加预算或更换种子。比较策略选了什么、实际花费了多少预算。可以导出每轮 JSON。

演示数据有意构造了“关键线索被删”和“初筛样本分布不代表完整评价”的条件。图表中的分数由程序实际计算，**不代表这些现象在真实任务中的发生频率**。

## 实验 01：工具输出压缩

三个自制案例：Unicode 规范化、0 与缺失值、带引号 CSV。背景通过日志为合成 fixture，实际修复候选是明确的 Python 实现，逐一运行输入／输出验收。

压缩方式：完整输出、只保留失败行、保留失败和环境行、自己写字面关键词。右侧可见日志支持手动修改。

固定规则诊断器仅从可见日志选择补丁，不读取隐藏验收结果或压缩模式。它非常简单，是为了隔离“信息是否还在”的影响；**它不是 LLM，也没有伪装成模型摘要**。人工选择补丁可以作为交互练习。

字符数与减少比例是实际计算；没有 tokenizer 依赖，因此不将字符数标成精确 token。字符上限可能把线索或错误截断，正适合观察它的影响。此版本不进行多轮重查，不能将单次字符减少写成端到端模型费用下降。

已知边界：任务描述和选项本身可能帮助人直接解题；它们不是与固定规则诊断器能力相同的对照。演示中的规则知道如何识别若干线索，不代表一般模型必定需要相同措辞。运行验收后会公开测试结果，用于学习；正式实验应冻结数据和评测器，并留出不可见测试。

## 实验 02：低成本试验与策略筛选

数据：自制英文客服工单，四类任务：账单、账户、物流和技术。标签是当前需要执行的动作。干扰样本提到已经解决／否定的其他主题。模板族在训练、开发和测试间共享，只有采样和实例 ID 分开，**不能用这里的高分证明真实业务泛化**。

真实训练：360 条训练数据；96 条开发数据；144 条独立测试数据。六个候选是：关键词捷径、词 TF-IDF + NB、词 TF-IDF + LR、双词组 NB、双词组 LR、字符组 LR。后五个在 CPU 上用 scikit-learn 训练，无需下载权重。

三种选择器：

- 随机整体验证：随机顺序挑候选，预算够时才完成一轮 96 条开发评价。
- 小试验一次排序：先测所有候选的小前缀，锁定排序，再按该顺序做完整开发评价。
- 逐轮加测淘汰：先用小前缀筛选，逐步缩小候选池、增加样本。它是教学用简化逐轮淘汰，不声称复现标准 Hyperband。

平局按页面列出的固定候选顺序打破，关键词捷径排在第一。此约定是透明的演示设定，不能从一次平局结果断言某种算法必然差。不同评价规模的证据不当成同样可靠：最终从已经看过最多开发样本的候选里按分数选一个。开发前缀的偏移条件和打散条件使用完全相同的完整语料。

**预算**：一次候选—开发样本评价算 1 单位；加测只算新增样本。同一策略不重复计费。各选择器共享固定、已训练的候选池，训练毫秒数单列，未算进选择预算。页面显示实际消耗和上限，未用完的预算不会假装花掉。这是评价样本预算，不等于 API token、训练时长或货币成本。

**防止泄漏**：选择策略只读取开发集。先锁定方案，再对测试数据评分。全候选开发／测试图表是事后诊断，不回流选择器；所有策略的测试结果都是真实预测。反复观察测试图表并调参后，该测试集便不再是正式研究意义上的最终测试集，需要另建新留出集。

## 文件与修改入口

| 文件 | 可以从这里学习什么 |
|---|---|
| `lab.py` | 任务、压缩器、真实修复验收、合成数据、训练与预算策略 |
| `server.py` | 标准库 HTTP 服务；只开放预定义实验，不执行用户代码 |
| `web/index.html` | 双实验界面与说明 |
| `web/app.js` | 请求、结果、图表、手动交互与导出 |
| `web/style.css` | 响应式布局 |
| `test_lab.py` | 信息删除反事实、预算账目与测试标签不影响选择的检查 |

最容易玩的修改：新增一个 CASES 案例；改保留关键词；增加一个候选分类器；把平局规则换成随机；改变开发前缀顺序。修改前后用同一批种子比较，保留原始结果。

## 真实模型诊断与以后扩展

第三页已实现实际模型选择补丁、四组输入对照、原始日志有限重查，以及逐次 token、调用数、耗时与最终验收记录。为避免旧案例题干提示答案，另建了 6 个成对开发任务；4 个预留任务本次没有向模型运行。仍属于诊断实验，不会自主编辑代码。当前压缩都是无需模型的行过滤，未计价的货币成本为 null。

实验 02 的候选池以后可换成真正由 Agent 提出的检索／训练配置，分别控制“产生什么候选”与“怎样选择候选”。该扩展尚未实现。

本项目以工具输出压缩、低成本试验与策略筛选为灵感，独立实现教学用实验；不声称复现 TokenWise 或 AgentPilot。
